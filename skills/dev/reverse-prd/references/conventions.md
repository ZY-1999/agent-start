# 约定（权威归属、编号、引用、版本）

多文档体系的失同步几乎都来自两件事：**同一信息写在两处**、**编号被复用**。这份文件是这两件事的防线。

## 一、权威归属

一个信息只在一个地方有权威版本，其他位置只能引用。

| 内容 | 权威位置 | 模块文档里怎么写 |
|---|---|---|
| 角色定义、权限矩阵 | `common/01-roles-permission.md` | 只列"本模块涉及的角色与操作"，链接到 C01 对应锚点 |
| 实体、字段、约束、ER | `common/02-data-dictionary.md` | 只列"本模块读写的实体和字段"，链接到 C02 实体小节 |
| 全局枚举、状态机总表 | `common/03-enums-states.md` | 本模块状态机的**转移细节**（副作用、证据）在模块 §5 展开 |
| 错误码、异常类、提示文案 | `common/04-errors.md` | 只列本模块抛出的错误码 + 触发场景 |
| 第三方集成、限流、配置项 | `common/05-nfr.md` | 只写"本模块受哪些约束影响" |
| 术语与代码写法对照 | `common/06-glossary.md` | 直接使用术语，不重复解释 |
| 代码地形、扫描范围、排除项 | `docs/codemap/`（项目图 + 每模块一份 feature 图） | 引用**本模块** CodeMap 的节点，不复制调用链描述，也不在 PRD 目录里另建代码索引 |
| 待确认问题 | 各文档自己的 `待确认` 节 | 模块内写全，A01 只做聚合与排序 |

跨模块规则（如"支付成功后订单状态变更"）写在**发起方模块**；被影响方写一句"受 M03 回调驱动，见 M03 §5"，不重复描述过程。

PRD 目录里**不设**代码索引类文档（文件清单、扫描命令、目录树、模块-文件对照表）。这类内容一旦落进 PRD，就会和 `docs/codemap/` 形成两份互相漂移的索引；需要时直接引用 CodeMap 路径。

## 二、编号

| 对象 | 格式 | 示例 |
|---|---|---|
| 总览 | `PRD-01` | — |
| 全局文档 | `PRD-C` + 两位序号 | `PRD-C03` |
| 模块文档 | `PRD-M` + 两位序号 | `PRD-M02` |
| 附录 | `PRD-A` + 两位序号 | `PRD-A01` |
| 模块 | `M` + 两位序号 | `M02` |
| 功能 | `F` + 模块号 + 序号 | `F02-01` |
| 业务规则 | `R` + 模块号 + 序号 | `R02-01` |
| 待确认 | `Q-M` / `Q-C` + 编号 + 序号 | `Q-M02-1`、`Q-C01-1` |
| 证据 | 仓库根相对路径 + `#` + 函数名 | `src/services/order.service.ts#createOrder` |

两条硬约束：

- **功能编号只增不重用。** 功能下线时标 `[已废弃]` 并注明对应代码版本，不删除、不把编号让给新功能——验收标准和待确认条目都靠编号回指，复用会让历史引用指向错误的功能。
- **证据以"文件 + 函数名"定位，行号仅作提示。** 行号会随改动漂移；重扫时按函数名重新校准，不按行号。非代码工件（DDL、配置、常量文件）没有函数名，定位到文件即可。

## 三、引用

- 证据路径一律**相对仓库根**，不写相对当前文档的 `../`——文档挪位置就失效。
- 跨文档链接用**相对文档的路径 + 锚点**（这是文档间导航，与证据路径规则不同）：`[C01](../common/01-roles-permission.md#3-全局权限矩阵)`。
- 模块文档只允许**引用**全局文档，不允许复制全局表格。
- 锚点写在链接里前先确认目标标题存在；标题改了要同步改锚点，否则链接静默失效。

## 四、版本

每份文档的 H1 下一行必须有版本块：

```markdown
> 文档编号：PRD-M02 ｜ 版本：v1.0（2026-10-23，基于 dev@41e9ecd 代码逆向整理）
```

模块文档再加一行定位信息：

```markdown
> 上级总览：[00-overview](../00-overview.md) ｜ 置信度：中 ｜ CodeMap：[M02](../../codemap/M02-订单.md)
```

规则：

- 编号在文档创建时确定，之后不变；拆分子模块时新编号顺延（`M02` 拆出 `M06`、`M07`），不复用旧号。
- 内容变更升 minor（`v1.1`）；错字、链接、格式修正升 patch（`v1.0.1`）。
- **代码版本变化必须动版本号**：有实质内容改动时按内容变更升 minor；仅版本块变化（重扫后确认内容无实质变更）升 patch——读者靠版本判断文档描述的是哪一版代码。
- 版本块里的 `基于 <分支>@<短 hash>` 必须是真实存在的 commit，不能用占位符蒙混。
- **不设变更记录。** 版本块是唯一的时间锚点，历史演进交给 git。文档只描述当前代码版本的状态，不写"上一版是什么"。
