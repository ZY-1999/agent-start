# 接口结构文件模板

每个模块一份：`docs/reverse-prd/interfaces/M<模块号>-接口结构.md`。文件名与内容语言一致（中文内容用中文名），目录名 `interfaces/` 保持英文。

这份文件承载**接口的入参与返回值结构**，是**实现侧对接资料，不是产品正文**。产品读模块 `§6` 的业务要素表即可；联调、接手、外包团队查结构看这里。物理字段名只出现在这里、`common/07-表结构DDL.sql` 与 `appendix/03-溯源台账.md`（全局三处），不进场景叙述。

## 写之前

- **来源二选一，写进文件头**：用户提供了接口文档 / swagger / openapi → 以对方契约为准；没提供 → 从代码（Controller / Service / Client / DTO / VO）反推，标「推导」。
- **结构用 jsonc**（JSON 示例 + `//` 行内注释），与目标系统一致；字段名照抄代码，注释写业务含义，确认不了的标 `// 待确认` 并开 Q。
- **依赖接口的"结构"记录本域实际发出的调用形态**，以对方契约为准；拿不到对方契约时写「外部契约未提供，仅记录本域调用形态」并开 Q。
- 对外接口与依赖接口在**同一文件里分两节**，不各开一个文件。
- **识别已废弃接口**：代码带 `/** @ignore */` 标记**且**前端无页面/路由调用它的接口，判定为已废弃。两个条件**同时满足**才废弃——只有标记但仍有页面调用，或只是暂时无页面，都不算。废弃接口不进「对外接口/依赖接口」两节，收进末尾的「已废弃接口」节，一行一条（接口标识 + 废弃证据 + 认定理由），不写入参/返回值结构。

## 模板

````markdown
# M02 · 订单 · 接口结构

> 实现侧对接资料，非产品正文。业务口径见 [M02-订单.md](../modules/M02-订单.md#6-对外接口)；物理取值编码见 [A03 §4](../appendix/03-溯源台账.md#4-取值编码映射)。
> 基线：后端 dev@41e9ecd ｜ 来源：推导自代码（未提供接口文档）／用户提供

## 一、对外接口（本域提供）

### 1. 创建订单

- 接口标识：`POST /api/orders`
- 调用方：前台商城
- 对应场景：S02-01

请求体：

```jsonc
{
  "skuId": "string",        // 商品编号，业务口径见 C02
  "quantity": 1,            // 购买数量，1–99
  "addressId": "string",    // 收货地址 ID，须在买家地址簿内
  "couponCode": "string?"   // 优惠券码，可空 // 待确认：是否支持叠加
}
```

响应体：

```jsonc
{
  "orderNo": "string",   // 订单号，18 位
  "amount": 1000         // 应付金额，单位分（编码见 A03 §4）
}
```

### 2. 查询订单

- 接口标识：`POST /api/orders/query`
- 调用方：前台商城、客服后台
- 对应场景：S02-01

请求体：

```jsonc
{
  "orderNo": "string?",   // 订单号，可选
  "buyer": "string?",     // 买家，可选
  "status": "string?",    // 状态，可选（取值见 C03）
  "timeRange": "string?"  // 时间范围，可选
}
```

响应体：

```jsonc
{
  "list": [
    {
      "orderNo": "string",   // 订单号
      "status": "string",    // 状态
      "amount": 1000         // 应付金额，单位分
    }
  ],
  "total": 10  // 总条数
}
```

## 二、依赖接口（本域调出）

### 1. 库存中心 · 预占

- 外部系统：库存中心
- 用途：下单时预占库存
- 触发时机：提交订单
- 失败后果：预占失败则下单失败，库存虚占

请求体（本域实际调用形态）：

```jsonc
{
  "skuId": "string",   // 商品编号
  "qty": 1             // 预占数量
}
```

响应体（对方返回）：

```jsonc
{
  "success": true   // 是否成功
}
```

> 外部接口结构以对方契约为准；此处只记录本域实际发出的调用形态，供排查与联调。

### 2. 支付平台 · 收款

- 外部系统：支付平台
- 用途：收款、退款
- 触发时机：提交支付、退款
- 失败后果：订单停在待支付；退款失败则资金未退

请求体：

```jsonc
{
  "orderNo": "string",   // 订单号
  "amount": 1000,        // 支付金额，单位分
  "channel": "string"    // 支付渠道（取值见 C03）
}
```

响应体：

```jsonc
{
  "payResult": "string"   // 支付结果 // 待确认：取值含义
}
```

## 三、已废弃接口

代码带 `/** @ignore */` 且前端无页面/路由调用的接口，一行一条；不写入参/返回值结构。废弃证据写清「代码标记 + 无页面调用」两处，认定理由写业务侧判断（如「功能已下线」「被新接口取代」）。

| 接口标识 | 废弃证据 | 认定理由 |
|---|---|---|
| `POST /api/orders/legacy-create` | `/** @ignore */` 标记；前端无路由调用 | 被「创建订单」取代，历史版本遗留 |
| `POST /api/orders/old-cancel` | `/** @ignore */` 标记；无页面调用 | 功能已下线 |
````
