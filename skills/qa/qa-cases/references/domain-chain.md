# 业务链路与跨模块检查点

`/qa-clarify` 扫断层、`/qa-cases` 找联动、`/qa-regress` 推影响面，都从这里出发。

**这份是项目无关的骨架**。项目自己的术语与规则不在本文件，在项目的 `docs/qa/glossary.md` 与 `docs/qa/knowledge/`（布局见 [`../../qa-flow/references/project-layout.md`](../../qa-flow/references/project-layout.md)）。骨架告诉你**该往哪看**，项目资产告诉你**这个项目实际怎么定**。

## 核心链路

```
访客 → 线索 → 跟踪 → 订单 → 合同 → 备件 → 售后 → 物流
                    ↓                              ↓
              OA（审批贯穿）                    ERP（物料/库存）
                    ↓                              ↓
            编码（主数据） → 成本湖 → 财务 → 采购
```

链路不是流程图，是**数据交接清单**。每一个箭头都是一次"上游产出变成下游输入"，也就是断层与 Bug 最集中的地方。

## 交接点与典型断裂

| 交接点 | 上游交出什么 | 下游依赖什么 | 常见断裂 |
| :--- | :--- | :--- | :--- |
| 访客 → 线索 | 来访记录、接待人 | 线索来源、关联客户 | 访客类型不同（普通/接待/长期驻场/外协），转线索的字段要求不同，被当成一套处理 |
| 线索 → 跟踪 | 线索与客户归属 | 商机负责人、阶段 | 线索分配后换人，商机归属没跟着换 |
| 跟踪 → 订单 | 报价版本、折扣审批 | 订单金额、折扣依据 | 报价改了版，订单还引用旧版价格 |
| 订单 → 合同 | 订单明细、交期 | 合同标的、履约节点 | 合同变更后订单不联动，两边数量对不上 |
| 合同 → 备件/售后 | 合同标的、保修范围 | 服务内容、是否收费 | 保修期内外的判定依赖合同日期，日期取签订日还是生效日没定义 |
| 售后 → 备件 | 派工单领用需求 | 备件出库、库存扣减 | 领用申请批了但没出库，派工单已完工 |
| 售后 → 物流 | 返修/发货需求 | 运单、签收 | 发货单已签收，服务单还是"运输中" |
| 任意 → OA | 审批单据与审批人 | 审批结果回写 | 审批人离职/换岗，单据卡在"审批中"无出口 |
| 任意 → ERP | 物料编码、客户编码 | 编码唯一性 | 并发创建时编码重号 |
| 成本湖 → 财务 | 成本归集结果 | 应收应付、开票 | 归集口径与开票口径不一致，对账对不上 |

用这张表的方式：写用例前找到本次需求落在哪个箭头，然后强制问一句"**这个箭头两边的数据，谁改谁跟着改**"。

## 通用术语基线

项目术语表缺位时，先按这套词对齐，再往项目表里补：

**单据状态**（大多数制造业单据可归到这七态）
草稿 → 提交 → 审批中 → 已审批 → 执行中 → 已完成 / 已关闭
旁支：已驳回（可回草稿）、已作废（不可恢复）、已撤回（回草稿）

**角色**
申请人、接待人、审批人、处理人/执行人、负责人、管理员
写用例时一律用"角色 + 范围"（服务工程师 / 华南区），不用人名。

**时间**
超时（超过约定时限未处理）、临期（接近时限）、逾期（已过时限）
时间类需求必须同时确认：起算点、时限值、边界取等号与否、超时后的动作。

**数据视角**
本人 / 本组织 / 本组织及下级 / 全部。权限类需求必须明确到这一层，不能写"有权限的人"。

## 六个跨模块检查点

每个需求都过一遍，命中就展开成用例，不命中就跳过。这六条覆盖了制造业系统里大部分"上线后才发现"的问题。

1. **状态回传** — 上游状态回退或作废，下游已生成的单据怎么办？是级联、锁定还是允许悬空？
2. **快照与实时** — 这个字段是下单时冻结，还是跟着主数据实时变？改了主数据，历史单据跟不跟？
3. **权限穿透** — 跨组织、跨项目、代操作、数据移交后，谁能看见谁的数据？
4. **并发** — 两人同时操作同一单据、同时抢同一库存、同时创建同一编码，谁赢、谁报错、报什么错？
5. **删除与作废** — 软删之后，下游的引用是显示"已删除"、隐藏、还是报错？统计口径是否排除？
6. **编码与序号** — 自动编码在并发、跨组织、跨年度时是否唯一？重置规则是什么？

## 用错的方式

- 把这张表当用例清单照抄——它只提示该问什么，具体断言必须来自本次需求
- 项目已有术语表时仍用基线词——项目表优先，冲突时以项目表为准，并把冲突记进疑问清单
- 拿通用链路当验收范围——链路再全，也不能替业务方决定这个版本该覆盖哪几段
