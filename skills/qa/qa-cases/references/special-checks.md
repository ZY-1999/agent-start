# 专项检查清单（默认不出，按需取料）

**当前团队现状：内部业务系统，使用者全是公司员工，无外部用户，暂无专项测试要求。**

所以 L4 默认**不出**。写完 L1/L2/L3 之后，在交接里写一句"本次不涉及专项测试"，这是正常交付，不是遗漏——纯内部系统硬塞一份性能/安全清单，只会稀释真正该跑的业务用例。

这份文件只在两种情况下打开：

1. 用户明确要做专项（客户要测试报告、上线前安全评审、系统要对外开放）
2. 需求出现了下面「常备七条」里的风险信号

## 为什么默认不出

内部系统的出事方式和对外产品不一样。外部产品怕被攻击，内部系统怕的是这三件：

- **谁能看到谁的数据**——普通员工看到全公司的合同金额、客户报价、成本价，这不是"漏洞"，是权限配错了
- **数据攒了三年之后还能不能用**——单据表到百万行，列表打不开、导出超时。这是内部系统最常见的事故，且上线时测不出来
- **两个人在同一张单上撞车**——审批、改价、派工这类操作会并发，不撞是因为现在用户少

前两条里，"权限"本来就是业务需求（需求文档会写"销售只能看自己的客户"），该在 L2 权限维度验；"数据量"是 L3 列表能力的边界。**所以它们不该待在专项层**——下面「常备七条」把它们拎出来归位。

## 常备七条：不单列 L4 文件，直接并进 L2 / L3

这七条内部系统照样会出事，但它们属于功能正确性，写进业务用例里就行：

| # | 风险 | 怎么验 | 归到 |
| :--- | :--- | :--- | :--- |
| 1 | 跨组织/跨项目看到别人的单 | 用 A 角色的账号，把列表中某条的 id 直接在 URL 里改成 B 的 | L2 权限场景 |
| 2 | 无权限的按钮还能点 | 无权限角色进入页面，再绕过前端直接调一次接口 | L3 权限 |
| 3 | 敏感字段（成本价、客户手机、银行账号）全员可见 | 用最低权限角色看列表、详情、**以及导出文件**三处 | L2 权限场景 |
| 4 | 单据量大了列表打不开 | 造同级数据 1 万条，打开首屏 | L3 列表边界 |
| 5 | 重复提交生成两条单 | 提交按钮连点 5 次 | L3 单点操作 |
| 6 | 两人同时审批同一单，出现两条审批记录 | 两个账号同时点审批 | L2 异常分支 |
| 7 | 导出文件在 WPS/Office 打不开或乱码 | 导出后用公司实际装的 Office/WPS 打开 | L3 列表能力 |

这七条都不需要单独建专项文件，也不需要专项工具。**它们只是容易因为"内部系统嘛"被跳过**。

## 扩展清单：只有真要出专项时才用

以下按类别取料，挑中的才写成 L4 用例，没挑的在覆盖检查表里写"不适用 + 理由"。不要原样抄进用例表——执行的人不知道从哪下手。

安全类里的越权项，如果已经在 L2/L3 按角色点界面验过，专项时只补**绕过前端直接调接口**这一种验法，不要原样重跑一遍功能用例。

### 性能

不做压测、不要 TPS，只验**业务能感知的慢与卡**。手工能复现的才是有效检查。

| 检查项 | 怎么验 | 判定标准 |
| :--- | :--- | :--- |
| 大数据量列表 | 造同级数据 1 万条，开首屏 | 首屏 ≤ 5s，翻页 ≤ 3s，不白屏 |
| 深分页 | 直接跳第 500 页 | 能打开，或明确限制最大页数并提示 |
| 组合筛选 | 多条件叠加 + 模糊查询 | 结果正确，响应 ≤ 8s |
| 大批量导出 | 导出 5 万行 Excel | 有进度提示，3 分钟内出文件，行数与筛选一致 |
| 大批量导入 | 导入 5 千行，含 10 行错误 | 有失败行明细，正确行入库、错误行不入库 |
| 并发审批 | 两账号同时审批同一单 | 只有一次成功，另一次提示已被处理，不产生重复记录 |
| 并发编辑 | 两人同时开同一表单先后保存 | 后者提示冲突或有覆盖记录，不静默丢数据 |
| 长时间操作 | 核心页面连续操作 20 个来回 | 无明显累积卡顿 |
| 批处理时段 | 定时任务执行时同时做业务操作 | 不被阻塞，或有维护时段提示 |

### 安全

不做渗透测试，只验常规权限与数据边界。

| 检查项 | 怎么验 | 判定标准 |
| :--- | :--- | :--- |
| 未登录访问 | 退出后直接粘内页 URL | 跳登录页，不闪现业务内容 |
| 水平越权 | 改 URL 里的 id 为他人单据 | 拒绝或提示无权限，不返回数据 |
| 垂直越权 | 低权限账号直接访问高权限菜单 URL | 拒绝 |
| 按钮级权限 | 无权限角色看页面 | 不显示或置灰；再绕过前端调接口试一次 |
| 组织隔离 | 跨组织查询/导出 | 只返回本组织数据 |
| 敏感字段脱敏 | 列表、详情、导出三处 | 按规则脱敏，导出文件同样脱敏 |
| 会话超时 | 超过超时时间再操作 | 要求重新登录，不继续原操作 |
| 重复登录 | 同账号两处登录 | 按既定策略，不出现串号 |
| 输入注入 | 查询框输 `' or 1=1 --`、`<script>` | 按字面查询或被转义，不报 SQL 错、不弹窗 |
| 上传限制 | 上传 .exe、超大文件、改后缀脚本 | 拒绝并提示，不落到可访问路径 |
| 操作日志 | 审批、删除、导出、改价 | 有日志：谁、何时、对哪条、改前改后 |

### 兼容

不做全浏览器矩阵，只验公司实际在用的环境。**制造业现场的车间电脑常有老版本浏览器和低分辨率**，这条比办公区更值得测。

| 检查项 | 怎么验 | 判定标准 |
| :--- | :--- | :--- |
| 浏览器 | 公司当前 Chrome / Edge 版本 | 布局不错位，功能可用，控制台无报错 |
| 分辨率 | 1366×768、1920×1080 | 关键按钮不被遮挡，宽表可横向滚动 |
| 导出文件 | 在目标 Office/WPS 打开 | 不报格式错误；合并单元格、公式、中文正常 |
| 打印 | 打印预览与纸质输出 | 分页正确、表头重复、无截断 |
| 扫码枪 | 扫单号、物料码录入 | 正确识别；**带回车符不误触发提交** |
| 标签打印机 | 打印标签 | 尺寸正确、条码可扫、中文不乱码 |
| 电子秤 / 读卡器 | 设备数据回填 | 数值格式正确；断连有明确提示 |

### 联调

系统与 ERP / OA / PLM / 财务对接时用。重点不是接口通不通，是**对不上时本地怎么办**。

| 检查项 | 怎么验 | 判定标准 |
| :--- | :--- | :--- |
| 正常调用 | 主流程触发外部接口 | 返回成功，本地状态与外部一致 |
| 外部返回错误 | 让外部返回失败 | 本地有提示，**不产生半成品数据**：回滚或挂待处理 |
| 外部不可用 | 断开外部系统 | 可降级或明确阻断，不静默丢单 |
| 超时 | 外部响应超时 | 有超时提示与重试入口，不无限转圈 |
| 重试幂等 | 同请求重发两次 | 外部只一条记录，本地不重复记账 |
| 数据一致性 | 本地改后同步，再核两端 | 关键字段一致；不一致有对账或告警 |
| 字段映射 | 新增/变更字段后核两端 | 两端都落地；空值与默认值处理一致 |

## 不写进 L4 的东西

以下属于专业测试范畴，手工作业做不了也不该做。需要时明确告诉用户"需要专项方案或工具支持"，不要用几条手工用例假装覆盖：

- 压力测试、容量规划、TPS / 响应时间分位数
- 渗透测试、代码审计、加密算法评估
- 全浏览器 × 全分辨率矩阵
- 自动化回归、性能基线监控
