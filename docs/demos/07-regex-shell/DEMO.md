# Demo 07：正则 / Shell / Sed —— 建议收尾

> 对应讲义章节：[2.7 场景七：正则 / Shell / Sed](../../index.html#s2-7) · 讲义中的"传统约 30 分钟 → AI 约 1 分钟"就是这里

## 目标

这类语法"每次都要现查、查完就忘"，任务本身 5 分钟，查语法 30 分钟——查询成本远高于执行成本，是 AI 增益最明确的场景。建议安排在演示环节收尾，并请观众现场出题。

## 传统方式 vs AI 方式

| | 传统方式 | AI 方式 |
|---|----------|---------|
| 耗时 | 30 分钟起步（查 man、试错、被 `\.` 和 `.` 折磨） | **1 分钟**（贴样本 + 说需求 → 拿到带注释的命令 → 跑通） |
| 产出质量 | 能跑就行，正则没人看得懂 | 命令带注释，正则逐段解释，可直接进 wiki |

## 演示步骤

1. 打开 `legacy/access.log` 给大家看格式，打开 `legacy/tasks.md` 宣布任务："现在开始计时，谁先做完举手"
2. **观众开始翻资料时**，你贴 Prompt 给 AI（几十秒出结果）
3. **现场跑 `ai-output/solution.sh`**（提前把 access.log 复制到 /tmp），投屏看输出——传统与 AI 的耗时对比在这一刻最直观
4. 逐条讲正则：AI 给的注释就是讲解材料
5. 加时赛：**请观众现场出一道自己工作中的日志/文本处理题**，10 分钟内交卷

## 推荐 Prompt

```text
我在处理服务器日志，样本行如下：

2026-09-12 14:23:51 INFO  [order-svc] 10.20.133.45 POST /api/orders status=200 cost=35ms

请用 bash 完成 3 个任务，每个任务给出：
a) 完整命令（GNU grep/awk/sed，可直接运行）
b) 正则的逐段解释（每一段匹配什么）
c) 一个容易踩的坑（比如贪婪匹配、转义、locale 影响排序）

任务 1：统计出现次数最多的前 5 个 IP
任务 2：只提取 status=500 的行里的"时间戳 + 接口名"，制表符分隔
任务 3：把 config.properties 里所有 env=test 批量替换为 env=prod，
       要求：先自动备份原文件，替换后展示 diff
```

## 讲解要点（对照 solution.sh 的注释讲）

- **任务 1**：`grep -oE` 只输出匹配部分（不输出整行）——很多人不知道 `-o`，于是用 awk 硬切
- **任务 2**：`awk '/status=500/ {print $1" "$2"\t"$6}'` 按空白分列；正则里 `\d` 在 grep 基本正则不可用（要 `-P` 或 `[0-9]`）——经典坑
- **任务 3**：`sed -i.bak` 一条命令完成"备份 + 原地替换"；提醒 macOS 是 BSD sed，`-i` 必须带参数——**AI 会主动提示跨平台差异**，这是查博客很难查全的
- **总结句**："任务本身 5 分钟，语法 30 分钟。以后你们只负责把任务说清楚，语法交给它。"

## 现场出题环节（加时赛）话术

> "现在你们任何一个人，出一道你工作中真实遇到过的文本处理题。我用它现场做。"
>
> —— 不管做不做得出来都有内容可讲：做出来了，是本场景的最好例证；做不出来，正好引出第三章边界五（何时效率反而更低）和第四章"迭代修正"。

## 失误预案

- 命令在 macOS 跑不通 → AI 提示过 BSD/GNU 差异，现场切 Linux 环境或让 AI 再适配
- 现场出的题太刁钻 → 迭代对话（"还是不对，注意 XX 字段可能有空格"），展示多轮逼近
- 完全没网 → 展示 `solution.sh` 与 `regex-explained.md`，用"预录结果"讲解正则
