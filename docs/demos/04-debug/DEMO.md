# Demo 04：排障（贴报错信息分析原因）

> 对应讲义章节：[2.4 场景四：排障](../../index.html#s2-4)

## 目标

展示 AI 排障的标准姿势：**报错 + 相关代码一起喂**，得到"直接原因 → 定位到行 → 修复选项"的三层回答。本 Demo 用的是 Java 程序员人人都踩过的坑：`ConcurrentModificationException`。

## 传统方式 vs AI 方式

| | 传统方式 | AI 方式 |
|---|----------|---------|
| 耗时 | 10 分钟（常见异常）~ 半天（冷门异常） | 30 秒 |
| 手段 | 复制异常名搜搜索引擎 → 翻 CSDN/博客 → 筛选过时答案 | 报错 + 代码贴进去，拿到针对**你这段代码**的答案 |
| 差别 | 答案是"别人的场景" | 答案是"你的代码 + 你的堆栈" |

## 演示步骤

1. 打开 `legacy/error.log`——只有一段堆栈，营造"凌晨收到告警"的现场感
2. 提问现场："谁一眼看出问题？"（认识 CME 的人会举手，追问"修复方案有几种、各自适用什么场景"，气氛就开始沉默了）
3. 把 `error.log` **连同** `legacy/BuggyApp.java` 一起贴给 AI
4. 对照 `ai-output/ANALYSIS.md` 展示三层回答
5. 有条件的话现场跑 `BuggyApp.java` 复现，再跑 AI 修复版确认

## 推荐 Prompt

```text
线上服务抛了下面的异常，相关代码一并贴上。
请按这个结构回答：

1. 直接原因（异常机制层面发生了什么）
2. 定位到具体是哪一行触发的，为什么
3. 给出至少 3 种修复方案 + 各自适用场景 + 推荐
4. 指出这段代码是否还有其他并发/逻辑隐患

[粘贴 error.log 堆栈]
[粘贴 BuggyApp.java]
```

## 讲解要点

- **"我为什么把代码也贴上"**：只贴堆栈 = 只能得到泛泛的百科解释；堆栈 + 代码 = 针对性诊断。**给 AI 的信息质量决定回答质量**
- **"注意第 4 条"**：让 AI 顺手做 Code Review，它通常会指出 `HashMap` 线程安全、金额用 double 之类的额外问题——排障 + Review 一次完成
- **排障的边界**（引出第三章）：AI 只能分析你给的信息。分布式链路、环境差异、数据问题导致的老大难故障，它没辙——那些还是靠人

## 常见追问（现场可能被问到）

**Q：如果我不知道哪段代码相关呢？**
A：Agent 阶段工具（Cursor / Claude Code）可以直接连上仓库按堆栈里的类名自己找到代码——这正是 1.2 节三个阶段的差距所在。

**Q：堆栈太长 / 日志巨大怎么办？**
A：先 grep 收窄再贴。AI 的上下文窗口有限（第三章边界二），"喂全量日志"既浪费又低效。

## 失误预案

- AI 诊断错误（比如说是线程安全问题）→ 追问"你确定吗？modCount 变化还有哪些来源"，展示迭代对话排障法
- 现场没有模型 → 展示 `ai-output/ANALYSIS.md`，重点讲 Prompt 的四段结构
