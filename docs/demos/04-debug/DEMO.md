# Demo 04：排障（贴报错信息分析原因）

> 对应讲义章节：[2.4 场景四：排障](../../index.html#s2-4)

## 目标

展示 AI 排障的标准姿势：**报错 + 相关代码一起喂**，得到"直接原因 → 定位到行 → 修复选项"的三层回答。本 Demo 用的是 Java 程序员人人都踩过的坑：`ConcurrentModificationException`。

## 传统方式 vs AI 方式

| | 传统方式 | AI 方式 |
|---|----------|---------|
| 耗时 | 10 分钟（常见异常）~ 半天（冷门异常） | 30 秒 |
| 手段 | 复制异常名搜搜索引擎 → 翻 CSDN/博客 → 筛选过时答案 | 报错 + 代码贴进去，拿到针对**你这段代码**的答案 |
| 差别 | 答案是"别人的场景" | 答案是"你的代码 + 你的堆栈" |

## 演示步骤

1. 打开 `legacy/error.log`——只有一段堆栈，营造"凌晨收到告警"的现场感
2. 提问现场："谁一眼看出问题？"（认识 CME 的人会举手，追问"修复方案有几种、各自适用什么场景"，气氛就开始沉默了）
3. 把 `error.log` **连同** `legacy/BuggyApp.java` 一起贴给 AI
4. 对照 `ai-output/ANALYSIS.md` 展示三层回答
5. 有条件的话现场跑 `BuggyApp.java` 复现，再跑 AI 修复版确认

## 推荐 Prompt

```text
线上服务抛了下面的异常，相关代码一并贴上。
请按这个结构回答：

1. 直接原因（异常机制层面发生了什么）
2. 定位到具体是哪一行触发的，为什么
3. 给出至少 3 种修复方案 + 各自适用场景 + 推荐
4. 指出这段代码是否还有其他并发/逻辑隐患

[粘贴 error.log 堆栈]
[粘贴 BuggyApp.java]
```
