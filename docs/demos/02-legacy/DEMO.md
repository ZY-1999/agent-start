# Demo 02：遗留代码理解（无文档的祖传代码）

> 对应讲义章节：[2.2 场景二：遗留代码理解](../../index.html#s2-2)

## 目标

展示 AI 的"阅读理解"能力：把一段**没有注释、命名晦涩、作者离职十年**的祖传代码贴给它，它给出逐段解释、补全注释，并**找出潜伏多年的 bug**。

这是传统工具（IDE、搜索引擎）完全做不到的事，也是对老程序员冲击最大的场景之一。

## 传统方式 vs AI 方式

| | 传统方式 | AI 方式 |
|---|----------|---------|
| 耗时 | 半天 ~ 数天（读代码 + 找人问 + 验证猜测） | 1 分钟出解释，半小时验证关键结论 |
| 手段 | 打断点单步跟、找前同事考古、猜魔法数字含义 | 贴代码 → 拿到结构化解释和风险清单 |

## 演示步骤

1. 先给观众看 `legacy/LegacyPricing.java`——**不要解释它**，停顿三秒，说"这是你们都接手过的那种代码"
2. 提问现场："谁能 30 秒内说出 `calc(100, 120, true, 6月15日)` 返回多少？"`（没人能）``
3. 贴给 AI，用下方 Prompt
4. 对照 `ai-output/EXPLANATION.md` 展示 AI 的三层产出：业务解释 / 补注释版本 / 风险清单
5. 重点讲 `d.getMonth() == 5` 那个 bug（月份从 0 开始，`5` 是六月不是五月）——**这就是 AI 阅读理解的价值**

## 推荐 Prompt

```text
这是我们项目里 2008 年的一段祖传代码，原作者已离职，没有任何文档。
请你扮演资深 Java 工程师，完成三件事：

1. 逐段解释这段代码的业务含义（我猜是某种折扣计算，帮我确认）
2. 给出补全注释后的版本（只加注释，不改任何逻辑）
3. 列出所有你发现的潜在 bug 和风险，按严重程度排序

背景：这是 B2C 商城的定价模块，t 是购买数量，f 疑似会员标记。
```
