# 演示种子数据与重置

Type: spec
Status: ready-for-agent
Parent: #1
Blocked by: #5

## Goal

管理员打开系统就能看到少量示例订单，并能一键把订单恢复成这批示例。

## Acceptance criteria

- [ ] 调用重置后，列表里恰好 8 条未删除订单，五个状态都出现：`PENDING` 2、`PAID` 2、`SHIPPED` 1、`COMPLETED` 2、`CANCELLED` 1。客户名称包含张三、李四、王五、赵六、陈七、周八。测试接缝为 MockMvc + `order_db_test`（Flyway clean+migrate，测试配置不在启动时播种）。证明示例集固定且覆盖看板需要的状态。
- [ ] 这 8 条的 `create_time` 落在服务器本地时区的今日到今日−6 天：今日 2 条，其余 6 天各 1 条。汇总接口的总订单数为 8，总金额为 `3515.16`，待支付数为 2，已完成数为 2，近 7 天每天订单数都大于 0。证明示例的日期和金额能让看板非空，且总金额仍由后端按 HALF_UP 计算。
- [ ] 重置前另建的订单，重置后不再出现在列表、前缀搜索和汇总里；再重置一次，未删除条数仍是 8，不是 16。库中被替换掉的行仍在且 `is_deleted = 1`。证明重置是逻辑删除后重放同一批示例，不是追加，也不是物理删除。
- [ ] 手工：默认启动（允许启动种子）在空库上打开订单页就能看到这 8 条；顶部导航的「重置数据」经确认后回到这 8 条，取消确认则不发请求。

## Scope

- **In**: 固定的 8 条示例、空库启动时写入、顶部导航重置按钮、`POST /api/orders/reset`。
- **Out**: 物理清空表、可配置的种子内容、导入导出、认证。不改订单号规则、金额规则和统计窗口。

## Design

外部接缝仍只有 HTTP。演示数据是一个深模块：调用方只看到「空库启动后有 8 条」和「一次重置回到这 8 条」。日期相对今天、逻辑删除后再插入、金额重算都藏在模块里。删掉它，示例规则会散到迁移脚本和页面里，过几天看板窗口还会空。

- **Interface delta**
  - `POST /api/orders/reset`，无请求体。成功 HTTP 200，`data` 为 `{ inserted: 8 }`。行为：把表中每一行 `is_deleted` 置为 1，再插入下面这 8 条。订单号仍由 spec #1 的规则生成。总金额不入参，按数量 × 单价、HALF_UP 两位计算。`create_time` 为对应本地日历日的 12:00:00。
  - 示例（客户名称 / 商品 / 数量 / 单价 / 状态 / 相对今天）：
    - 张三 / 机械键盘 / 2 / 199.50 / PENDING / 0
    - 李四 / 显示器 / 1 / 1299.00 / PAID / 0
    - 王五 / 鼠标 / 3 / 89.90 / SHIPPED / −1
    - 赵六 / 耳机 / 1 / 399.00 / COMPLETED / −2
    - 张三 / 扩展坞 / 1 / 259.00 / CANCELLED / −3
    - 陈七 / 键盘 / 2 / 150.25 / PENDING / −4
    - 李四 / 摄像头 / 1 / 189.00 / COMPLETED / −5
    - 周八 / 音箱 / 4 / 99.99 / PAID / −6
  - 八条总金额为 `3515.16`。状态计数为 PENDING 2、PAID 2、SHIPPED 1、COMPLETED 2、CANCELLED 1。
  - 默认配置在应用启动且未删除订单数为 0 时执行与重置相同的插入（不先做删除）。已有未删除订单时启动不插入。测试配置关闭这段启动插入；重置接口两种配置都可用。
  - 页面：顶部导航「重置数据」。确认后调用重置并刷新当前页数据；取消不发请求。订单页与汇总页都能看到该按钮。
- **Internal architecture**
  - Web → Service → DAO。示例内容与「相对今天」的时间只在 Service。启动插入调用同一个插入动作，不复制一份列表。
  - 不用 Flyway 写入这 8 条。不物理删除。

## Rework on failure

失败时去掉启动插入、重置接口和按钮。订单 CRUD 与看板仍在。重做本 spec。
