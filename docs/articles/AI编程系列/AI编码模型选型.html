AI 编码模型选型指南
档位、价格与基准怎么读

选模型时，真正容易踩坑的往往不是"买哪家"，而是三个想当然：最贵的一定最好、跑分可以直接横比、选完就能用很久。

01厂商都在按档位卖能力

很少有"永远最好"的模型，更常见的是把任务派给合适的档位。

所有厂商的产品线都遵循同一套商业逻辑：把能力切成几档，按能力收费。以 Anthropic 现役产品线为例，从高到低是：

档位定位典型用途
Mythos受限顶级档，需资质审核，有出口管制风险受管制的高能力场景
Fable / Opus通用旗舰，攻坚主力复杂重构、疑难排查、架构级任务
Sonnet均衡档，性价比最优日常 Agent 任务、多数开发工作
Haiku小快档补全、批量小改、分类摘要

Gemini、GPT 和国产各家也是类似切法，只是名字不同。从这套分层里，至少能抽出两条纪律：

  1. 别让所有人和所有任务都跑最高档。补全、单测、小改用中档或快档通常就够，旗舰留给真正难的任务，账单差会非常明显。
  2. 关键流程不要绑死一家模型。顶级档可能因监管、出口管制或安全事件被限权或临时下架，2026 年已经出现过，要留一条替补通道。

还有一个隐藏旋钮：思考强度。同一模型在 low / medium / high 档下，能力和账单差异巨大。宣传页引用的往往是最高档的分数，你日常跑的却是默认档。拿"最高档的分数"评估"默认档的成本"，是采购里最常见的一笔糊涂账。

03基准分数怎么读：五个陷阱

看到"XX 榜单第一"，先核对这五件事。

  1. 版本不同不可比。Terminal-Bench 2.1 和 4.0 难度差一个量级，同一模型 2.1 拿 90 分、4.0 只有 31 分。看到"TB 90 分"先问版本号；版本号没有的宣传，默认存疑。
  2. 思考档位不同不可比。同一模型 high 档和默认档分数差异巨大，高档的 token 消耗是低档的数倍。分数背后是账单。
  3. 厂商自测有偏差。评测框架、工具链、提示词各家都不同；以第三方官方榜为准，与厂商自报值交叉验证。
  4. 老基准会过时。SWE-bench Verified 已冻结，新一代模型在上面没有条目，榜首 79.2% 是老时代成绩；LiveCodeBench 和 Aider 已停更，引用这两个分数的基本是旧材料。
  5. 模拟环境不等于你的仓库。基准是"标准题"，你们的遗留系统、私有框架、内部工具链都不在题里。基准只用来筛掉明显不行的；最终要用自己仓库的 20~30 个真实任务做双盲 A/B，记录人工修正工时。

当前主流基准的品牌识别

2026 年还在维护、可以引用的：Terminal-Bench 4.0、SWE-bench Pro、DeepSWE、NL2Repo、CursorBench。看到 SWE-bench Verified、LiveCodeBench、Aider Polyglot 的分数，先确认基准状态再引用。

04任务分级选档矩阵

比"换成更便宜的模型"更有效的，通常是给每类任务匹配档位。

任务类型建议档位理由
补全、改注释、重命名快档 / 小模型量大要求低，用旗舰是浪费
写单测、文档、解释代码中档性价比最优
日常功能开发、跨文件小重构中档（高档备选）需要推理，但吃不到极限能力
疑难 bug、大型重构、性能优化旗舰 / 高档失败一次的代价远超 token 成本
长任务编排（多子代理、云端 Agent）旗舰 + 严格限额长链路错误会累积放大
涉密 / 核心系统私有化部署模型数据不出内网优先于能力

再配三件小事：打开提示缓存，把规则文件放在固定前缀位置；控制上下文长度，别整仓塞进对话；每月按团队复盘账单。分级选档加上这三件，很多团队能把账单砍掉一半左右，具体幅度要看自己的任务画像。

05私有化：数据不出内网时怎么选

上下文里可能有客户数据或个人信息时，常见选择是开源权重模型加内网部署，而不是把整仓送到公网 SaaS。

可私有化的现实候选：DeepSeek-V4.1-Flash（MIT，单位成本最低）、Qwen3.8-27B（Apache-2.0，小尺寸适合少量卡起步）、GLM-5.3-Flash（开源 TB 4.0 最高分 GLM-5.3 的轻量同系档）、Kimi-K3 与 MiniMax-M3（规模更大，部署门槛高）。落地前四件事想清楚：

1

资源需求自己压测

没有任何厂商公布"最低显存/卡数"，官方只给部署配方。按宣传页采购是不可靠的，先拿真实负载压测。

2

"开源权重"不等于"完全开源"

许可差异大（MIT / Apache-2.0 / 自定义），商用与再分发条款要法务确认过再上生产。

3

MoE 的"激活参数小"不代表部署便宜

推理时激活的参数少，但整个权重都要装进显存。采购算的是全量权重的账，不是激活量的账。

4

私有化不等于只买模型

还得配 harness（客户端）、网关、审计日志、凭据管理。模型之外这套配套的成本，常常被初预算漏掉。

06订阅还是按量

判断标准很实际：你们一个真实任务大概烧掉多少 token。

Agent 跑一个真实任务，读文件、跑测试、看报错、反复修正，很容易烧掉数十万 token。偶尔问一句报错，按量计费就够；高频开发通常订阅更划算，"Coding Plan"就是为这种用量设计的。国内入门价可参考 GLM Coding Plan Lite：月付 ¥118，连续包季折合 ¥94.4/月。海外个人订阅多从 $20/月起。

建议姿势

先用按量计费跑两三周，量出团队的真实用量画像（人均日/月消耗、任务分布），再据此谈订阅或企业协议，避免一上来就买大套餐，也避免按错误档位做预算。

07结论：国产 + 海外双轨

下面三条可以直接写进内部选型备忘。

  1. 双轨并行，别赌一家。日常和涉敏项目可以优先国产模型（价格、私有化、合规路径更清楚），少数攻坚任务再上海外旗舰。用统一网关把差异挡住，团队就不必维护两套完全不同的工具链。顶级模型被限权或下架已经发生过，替补通道建议每季度演练一次。
  2. 按档位判断能力，不要只记品牌。开源档（GLM、DeepSeek）对不少日常任务已经够用；真正拉开差距的，仍是旗舰档处理疑难重构和长任务时的表现，额度应留给这些场景。
  3. 跑分只用来筛掉明显不行的。同一基准、同一版本、同一思考强度，三个条件缺一个，比较就不成立。最终拍板还是用自己仓库的 20~30 个真实任务做 A/B。

这个市场输出单价可以差约 100 倍。更省钱的决定通常不是"换成某家便宜模型"，而是给每类任务配对档。
