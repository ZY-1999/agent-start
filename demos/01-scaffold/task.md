# 演示输入：订单管理需求（平时口头接到的需求原文）

新做一个订单管理的模块，先不接数据库，内存里存就行。

订单要有：编号、客户名、金额、状态（待支付 / 已支付 / 已取消）、创建时间。

要有的功能：

1. 创建订单（客户名必填，金额必须是非负数，保留两位小数）
2. 修改订单（只能改客户名和金额）
3. 取消订单（逻辑上就是删掉）
4. 查单个订单（查不到要报明确的错，别返回 null 让调用方猜）
5. 列表查询（可以按状态筛，不传状态就查全部）

测试要覆盖：正常流程、查不到的异常、状态过滤。命名按公司的阿里规范来。

> 传统做法：建 5 个文件，40 分钟起步。
> Demo 做法：把上面这段话整理成结构化 Prompt（见 DEMO.md），30 秒出结果。
