# 正则逐段解释（AI 参考产出，讲解材料）

> 现场对照 `solution.sh` 用这份材料讲解"AI 不只给命令，还给可教学的解释"。

## 任务 1 的正则：`[0-9]{1,3}(\.[0-9]{1,3}){3}`

| 片段 | 匹配什么 | 备注 |
|------|----------|------|
| `[0-9]` | 单个数字 | 等价 `\d`，但 grep 基本正则不认 `\d` |
| `{1,3}` | 重复 1~3 次 | IPv4 每段最多 3 位 |
| `\.` | 字面量的点 | 不转义的 `.` 匹配任意字符，是新手第一大坑 |
| `(...){3}` | 分组重复 3 次 | 对应 `.xxx` 三组 |

## 任务 2 的 awk 分列

日志按空白自然分列：

```
$1=2026-09-12  $2=14:23:53  $3=ERROR  $4=[order-svc]  $5=10.20.133.45  $6=POST  $7=/api/orders  $8=status=500 ...
```

- `/status=500/` 是"模式"，只对匹配行执行 `{}` 里的动作
- 比 sed/grep 切字符串稳定：列内含特殊字符也不受影响

## 任务 3 的 sed：`s/env=test/env=prod/g`

| 片段 | 含义 |
|------|------|
| `s/旧/新/` | 替换第一个匹配 |
| 结尾 `g` | global，替换行内**所有**匹配——本任务 config 里有 3 处，不写 g 只改每行第一处 |
| `-i.bak` | 原地修改并留备份 |
| `$/` 锚定 | `s/env=test$/env=prod/` 只匹配行尾，防止误伤 `env=test2` |

## AI 主动提示的三个坑（讲这些最能赢得老程序员认同）

1. **uniq 只合并相邻行**——不先 sort 直接 uniq -c，统计结果是错的
2. **GNU vs BSD**：macOS 的 `sed -i` 必须带后缀参数；`grep -P`（PCRE）在 BSD/macOS 默认不可用
3. **locale 影响排序**：`sort` 在不同 locale 下对数字/符号排序不同，脚本里常加 `LC_ALL=C sort`
